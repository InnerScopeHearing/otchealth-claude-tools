# SWARM operating lessons

These source-free notes describe demonstrated cases, not universal product guarantees. Reverify changing behavior in the affected runtime. Add only corrections that change decisions or avoid waste.

## Bounded help beats an idle approval loop

Observed 2026-10-01: a cloud worker completed startup and its synthetic marker, then waited about 16 minutes for its existing checkpoint bridge approval. After one scoped approval, the bridge returned `forbidden_role`; native own-seat checkpoint binding was absent. A catalogue entry and exposed bridge did not establish callable role permission. The correct help packet is the missing own-seat binding, exact rejection correlation, untouched checkpoint state, and the safe same-seat repair needed. Do not switch to the CTO identity, repeatedly ask for permission, or rerun the startup and marker. Pause conflicting work while the binding owner repairs the real seam. Provider approval waiting is wall-clock time and must be reported at the worker checkpoint.

Evidence: WeFunder cloud technical admission 6abf3baa-08a8-83e8-b0f8-a758ff0fc225, rejection correlation 912ce5bd-b2af-4e4d-a0b4-9f1d5362225c, exact own-seat recall returned zero records. This is not permission to expose campaign or investor data to another seat.

## Preserve isolation when a cloud project mode is unavailable

Observed in the project creation UI 2026-10-01: project-only memory says it cannot use cloud Work. Do not weaken a protected project's memory scope to make a cloud task start, or infer cloud readiness from a newly named folder. Preserve the user's protected Chat memory boundary and escalate the exact cloud Work limitation. A separately isolated cloud runtime may be appropriate only within the existing authorized architecture, with its own identity, restore, memory and laptop-disconnected acceptance. This observation is product/runtime-specific and may change.

## Verify delayed UI state before another mutation

Observed in the in-app browser 2026-10-01: a project dialog appeared after the first post-action accessibility snapshot; a subsequent selector saw no matching background button because the modal was already open. Take one fresh visible-state observation and resolve the actual dialog before another click. Do not repeat a creation, rename or move just because an immediate snapshot was unchanged. An unrelated destination or unknown write result requires exact readback and a frozen mutation lane, not blind coordinate retries.

In the same runtime, an accessibility value setter did not persist a project-instructions textarea. Native text input produced the actual Cancel/Save controls. Treat an edited value as a draft until the supported Save completes and reopening the form shows the exact saved text. Do not assume every field autosaves or every successful setter fired the application's edit handler.

## Keep discovery and evidence small

Discover tool names first, then read metadata for the exact intended tool. Do not print a fleet-wide tool-description inventory, full operational note history, or repeated healthy startup merely for status. Prefer exact record/job IDs, bounded local searches, short result projections, and deterministic counts. A returned tool-call envelope can contain sensitive arguments even when tool outputs are excluded; request a source-free technical owner receipt instead of reading protected chat history in a company seat.

## Test minimized output on failures as well as success

Observed at PR503 head e26ffb69: Twilio list helpers replaced absent response collections with empty arrays, and raw provider error messages could reach the generic tool error. A count-only success projector therefore did not prove truthful or source-free failures. The bounded candidate correction validates collection shape and request bounds, denies other callers before provider calls, and returns a fixed sanitized failure. Actual synthetic helper, caller, bounds and failure tests ran in cloud CI36979235175 at commit86050bc6 and passed. This is source/CI acceptance only; no deployed provider capability or full COO access is established. Cost target: avoid false-zero diagnoses and risky payloads without repeating production tests.
